# Аватарки игроков и индикатор говорящего в игре — дизайн #233

Дата: 2026-10-15. Задача: [#233](https://github.com/MythHand/ReleaseBoardGameP2P/issues/233).
Ветка: `feat/233-player-avatars-speaking`. Основа: `main` / `3e9f291d`.
Статус: дизайн согласован владельцем в чате 2026-10-15 по частям; продуктовый код ещё не начат.

## 1. Цель и согласованные решения

[PR #224](https://github.com/MythHand/ReleaseBoardGameP2P/pull/224) сделал в `@release/ui` и playground аватарки-пресеты, модалку настроек игрока (`PlayerSettings`), карандаш на своей строке (`PlayerSlot.onEdit`), состояние «ник занят» на экране приглашения и кольцо говорящего (`Avatar.speaking`). Фронт этих пропсов не передаёт. Задача — довести это до игры: протокол, проверки хоста, хранение, проводка в UI и определение говорящего.

Решения владельца:

1. **Выбор аватара запоминается у игрока** (в браузере) и уходит хосту как пожелание при входе. Хост выдаёт его, если он свободен, иначе — случайный свободный.
2. **Ник уходит в сеть при закрытии модалки, аватар — сразу по клику.**
3. **Говорящий определяется анализатором в нашем Web Audio-графе — для всех**, включая себя. Это осознанно расходится с формулировкой #224 («из сети, не анализом звука»): входящий звук и так идёт через наш граф, один механизм для своих и чужих, одинаково работает в браузерах, без зависимости от внутреннего `peerConnection` PeerJS.

Вне задачи: аватар на карточке за столом (`Seat` в `@release/ui/table`), смена ника во время матча.

## 2. Данные и протокол

### 2.1 Модель (`apps/frontend/src/network/types.ts`)

- `PeerInfo.avatar?: string` — id пресета из `PRESET_AVATARS`. Есть только у ролей `host` и `player`; у `guest` (зритель) и ботов нет. Едет в существующих `PEER_JOINED` / `PEER_LIST`.
- `Seat.avatar?: string` — фиксируется в `GAME_STARTING` вместе с рассадкой. Статистика и «Participants» строятся по рассадке, а не по живому ростеру, — без этого у вышедшего игрока аватар пропал бы.
- `JoinRequestPayload.avatar?: string` — пожелание. `parseJoinRequestPayload` принимает только строку; хост дополнительно сверяет с каталогом, неизвестный id игнорирует.

### 2.2 Новые сообщения

| Сообщение | Направление | Назначение |
|---|---|---|
| `PROFILE_UPDATE { name?: string; avatar?: string }` | гость → хост | Смена ника и/или аватара. По образцу `PLAYER_READY`. |
| `PROFILE_REJECTED { reason: 'name-taken' \| 'avatar-taken' \| 'not-in-lobby' }` | хост → отправитель | Откат оптимистичного выбора при гонке. |
| `JOIN_REJECTED.reason: 'room-full' \| 'name-taken'` | хост → входящий | Отказ во входе с занятым ником. |

`ErrorKind` в `useLobby` расширяется значением `'name-taken'`.

### 2.3 Чат

Новое системное событие `ChatSystemEvent`: `{ kind: 'memberRenamed'; memberId; from; to }`. Рендер в `RoomChat` через существующий ключ `chat.system.memberRenamed` (`{{from}}` / `{{to}}`), по образцу `roleChanged`. Смена аватара в чат не пишется.

### 2.4 Хранение (`apps/frontend/src/shared/lib/persistence.ts`)

- Ключ `release:avatar`, без срока жизни: `readAvatar(): string | null`, `writeAvatar(id)`. Пишется, когда хост подтвердил аватар — пришёл `PEER_JOINED` со своим id и новым `avatar`, а у хоста сразу после применения.
- Подтверждённый новый ник сразу пишется в `release:session` (`writeSession({ ...stored, name })`). Иначе хост отклонит реконнект сверкой имени (`useLobby.ts:1008`).

### 2.5 Размещение логики

Всё, что решает хост, — чистые функции в `network/lobby/`: новый `profile.ts` (выдача аватара, проверка ника, обработка `PROFILE_UPDATE`) и правки в `host.ts` / `admission.ts`. `useLobby.ts` только подключает их к транспорту.

## 3. Правила хоста

### 3.1 Выдача аватара

`assignAvatar(state, wish, exceptPeerId)`: пожелание, если оно есть в `PRESET_AVATARS` и его не держит другой игрок; иначе случайный свободный; если свободных нет — `undefined` (инициал). Пресетов 19, игроков максимум 6.

| Случай | Откуда пожелание |
|---|---|
| Хост создаёт комнату | свой `release:avatar` |
| Вход игроком (`handleJoinRequest`, роль `player`) | `JOIN_REQUEST.avatar` |
| Реконнект (лобби или место в матче) | `JOIN_REQUEST.avatar` — это и есть прежний аватар |
| Зритель → игрок (`setParticipantRole`) | нет, случайный свободный |
| Игрок → зритель | аватар снимается и освобождается |

### 3.2 Проверка ника

`nameTaken(state, name, exceptPeerId)` — общая для хоста и для локальной подсказки в модалке. Сравнение после `trim()` и без учёта регистра. Ник занят, если совпадает:

- с ником другого участника ростера (хост, игрок, зритель);
- с любым из `botNames(hostId, MAX_BOTS)`. Резервируются все пять возможных имён ботов, а не только текущие: иначе добавленный позже бот получит имя живого игрока. Перестановка в `botNames` не зависит от `count`, так что первые `MAX_BOTS` имён стабильны.

Пустой ник отклоняется. На реконнекте исключается сам вернувшийся (`returningLobbyPeer` / `returningSeat`).

### 3.3 Обработка `PROFILE_UPDATE`

- Отправитель должен быть в ростере, `where === 'lobby'`, матч не идёт. Иначе — `PROFILE_REJECTED 'not-in-lobby'`.
- `avatar` учитывается только от `host` / `player`; от зрителя поле игнорируется. Аватар должен быть в каталоге и не занят другим игроком, иначе — `'avatar-taken'`.
- `name` проверяется по 3.2, иначе — `'name-taken'`. Если в одном запросе отклонено хоть одно поле, не применяется ничего.
- Успех: обновлённый `PEER_JOINED` всем; при смене ника — системная запись `memberRenamed` в чат (`CHAT_ENTRY`).
- Хост меняет свой профиль тем же вызовом напрямую, без сети, — тот же путь, что `setReady` хоста.

## 4. Интерфейс (`apps/frontend`)

### 4.1 Лобби (`pages/lobby/_LobbyView.tsx`)

Поведение переносится с `@release/ui/screens/Lobby` (эталон читается и переписывается, не импортируется):

- Своя строка (`PlayerSlot`, игрок или зритель) получает `onEdit` и открывает `Modal` с `PlayerSettings`. Зрителю — без сетки аватаров. Чужим строкам передаётся `avatar`, без `onEdit`.
- Черновик ника — локальный. `nicknameTaken` в модалке считается функцией из 3.2 по копии ростера.
- Клик по аватару — `PROFILE_UPDATE { avatar }`; выбор подсвечивается оптимистично; при `PROFILE_REJECTED` — откат к аватару из ростера.
- Закрытие модалки — если черновик непустой, свободный и отличается от текущего ника, `PROFILE_UPDATE { name }`. Отказ хоста — тост с `nicknameTaken`, ник остаётся прежним.
- Переход в игру при открытой модалке закрывает её без отправки.

### 4.2 Экран приглашения (`pages/lobby/_InviteScreen.tsx`)

`errorKind === 'name-taken'` — ошибка на поле ника с текстом `nicknameTaken`, как в `InviteStory`. Повторная попытка — тем же путём, что сейчас после `room-full`. Пожелание аватара берётся из `release:avatar`.

### 4.3 Где показываются аватар и кольцо

| Место | `avatar` | `speaking` |
|---|---|---|
| Строки лобби (`PlayerSlot`) | `PeerInfo.avatar` | да |
| Чат (`features/chat`) | текущий `PeerInfo` автора по `memberId`; ушедший — инициал | нет (у блока нет пропса) |
| «Participants» за столом | `Seat.avatar` | да |
| Статистика (`entities/game/stats` → `toStatPlayers`) | `Seat.avatar` | да |
| Голос (`features/voice-chat/model.ts` → `toVoiceParticipants`) | `PeerInfo.avatar` | да |

### 4.4 `useSpeaking(): Set<MemberId>`

Один хук для всех потребителей. Правила показа поверх сырого сигнала из голосового слоя:

- видно, только если я в голосе (`status` `connected` / `interrupted`);
- не видно для участника, которого я замьютил;
- никогда — если у говорящего выключен микрофон;
- своё кольцо — когда я говорю с включённым микрофоном.

### 4.5 Копирайт

Все строки через `t()`. Нужные ключи (`playerSettings.*`, `nicknameTaken`, `chat.system.memberRenamed`) уже есть в en/ru; любой новый ключ добавляется в оба каталога.

## 5. Определение говорящего (`network/voice/`)

### 5.1 Детектор — `voice/levels.ts`

Чистая логика без браузерных API: на вход — уровни RMS по участникам на каждом такте, на выход — набор говорящих. Гистерезис: включение выше порога `SPEAKING_ON_RMS ≈ 0.02`, выключение после `SPEAKING_HOLD_MS ≈ 300` ниже порога — кольцо держится на фразу и не мигает по слогам. Константы с комментарием, подстраиваются на живой проверке.

### 5.2 Граф (`voice/audio.ts`)

- `attach()`: `MediaStreamSource` → `AnalyserNode` (`fftSize 512`) параллельно узлу громкости. Громкость и локальный мьют стоят после анализатора и не влияют на определение. `release()` отключает анализатор.
- `setMicrophone()`: анализатор на живом треке микрофона (не на тихом треке). При выключенном микрофоне себя в наборе нет.
- Опрос — один `setInterval` (~100 мс) на весь граф, не `requestAnimationFrame`: в фоновой вкладке rAF замирает, а голос идёт. Таймер работает, только пока есть хотя бы один анализатор; `dispose()` его останавливает.
- Уровень — RMS по `getFloatTimeDomainData`.
- API: `VoiceAudio.subscribeSpeaking(listener: (ids: ReadonlySet<string>) => void): () => void`. Вызывается только при изменении набора. Свой id — `selfMemberId`.

### 5.3 Снимок

`VoiceSnapshot.speakingMemberIds: string[]`. `runtime.ts` подписывается на `audio.subscribeSpeaking` и публикует набор через существующий `subscribe` — до `useRoomVoice` без новых каналов. Сигнал и правила показа разделены: правила — в `useSpeaking` (4.4).

### 5.4 Анимация

Кольцо — переход `border-color` в `apps/ui/src/primitives/Avatar/Avatar.module.css`. Под `prefers-reduced-motion: reduce` добавляется `transition: none`.

## 6. Проверка

- **Unit, `network/lobby/`:**
  - `assignAvatar`: пожелание, занятое, неизвестный id, свободных нет;
  - освобождение при уходе в зрители, выдача при переходе в игроки;
  - `nameTaken`: регистр, пробелы, игрок, зритель, хост, боты (включая ещё не добавленных), исключение себя;
