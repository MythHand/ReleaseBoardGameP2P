## Ограничение реального P2P прогона

`pnpm dev:p2p` поднял настоящий PeerServer на :9000 и frontend на :5174. Изолированные браузеры host/player/spectator/late открыли интерфейс, хост создал лобби, формы игрока и зрителя отправились и оставались connecting. PeerServer зарегистрировал клиентов, SDP offer/answer обменялись, но ICE перешёл в failed/disconnected; DataChannel не открылся, наблюдатель получил 0 игровых кадров.

Проверены обычный Chrome-клиент без наблюдателя, диагностические варианты локального ICE/mDNS и loopback, разрешение local-network-access. Независимая локальная пара RTCPeerConnection также не открылась за 5 секунд. Firefox из установленного runtime не стартовал: `sandbox_extension_issue_file_to_process ... Operation not permitted`. Эти результаты указывают на ограничение браузерного окружения; конкретная системная причина не установлена. Настройки игры, протокол и системные сетевые службы не подменялись.

Дополнительная проверка в трёх чистых вкладках встроенного браузера Codex дала тот же результат: игрок и зритель остались connecting, хост видел 0 зрителей. Хост смог добавить BitBot и запустить локальную партию. Этот результат не подтверждает сетевую игру с ботом.

**Не подтверждены реальными браузерами:** вход до/после старта, wire privacy, reload зрителя/хоста, kick с прекращением доставки, заполненная квота, игра с ботом через сеть, stats → lobby → reload → rematch. Соответствующие автоматические тесты зелёные. Полный ручной P2P прогон нужен в окружении с рабочим WebRTC перед публикацией.

## Независимое ревью

Независимый reviewer `/root/final_review` (gpt-6-astra/high) проверил весь диапазон `47a41b85..f6bef8bd`. Critical не найдено. Все три Important замечания приняты и исправлены одним проходом с воспроизведением RED → GREEN:

1. Несколько SYNC до монтажа Board или внутри одного обновления React теперь накапливаются в сессии вместе с отдельной границей catch-up. Интеграционный тест передаёт resync, живой draw и пустой SYNC до монтажа useGame, проверяя полный журнал, сохранение и отсутствие повторной анимации истории.
2. Публичная раздача поглощает только исходные события; живые события ждут в очереди. Её shadow остаётся на исходном снимке. Тест компонента Board в jsdom проверяет один draw после раздачи и пять прилётов к местам: четыре карты раздачи и одну живую.
3. Отказ room-full передаётся в обе поверхности Board reconnect и общий Table. Английский и русский текст объясняет отсутствие мест; page-level тесты проверяют Retry и подтверждённый Leave с имеющимся снимком игры и без него.

Второе ревью не проводилось: проверены регрессионные тесты и полный набор после исправлений, повторное одобрение reviewer не подразумевается.

**Отложенное Minor:** форма входа не показывает доступность другой роли из joinAvailability после отказа. Отказ выбранной роли объяснён, но свободную альтернативу пользователь узнает после дополнительной попытки.

**Принятые решения и риск:** реальный P2P прогон оставлен неподтверждённым после неудачного ICE в Chrome; после проверки во встроенном браузере это ограничение сохранено. В обоих случаях цена решения — сетевой дефект может остаться до проверки в рабочем WebRTC-окружении. Существующая видимость neutralize503.methods/crush.methods между игроками сохранена согласно согласованному объёму; для зрителей поля удалены. Цена этого решения — прежняя доступность информации между игроками остаётся и требует отдельного продуктового решения.
