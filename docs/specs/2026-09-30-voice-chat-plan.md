# Voice Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подключить голосовой чат комнаты через прямые PeerJS-соединения, с режимом слушателя и общим frontend-сервисом разрешений.

**Architecture:** Игровые DataChannel сохраняют звезду через хоста; аудио использует один MediaConnection на пару участников. Host-authoritative voice-roster и runtime комнаты управляют звонками, Web Audio и восстановлением. Browser access изолирован в `shared/lib/permissions`, UI получает состояние и callbacks через feature-адаптер.

**Tech Stack:** Node.js >=24, pnpm 9.15.0, TypeScript 6, React 19, существующий PeerJS 1.5.5, WebRTC, Web Audio, Vitest и Testing Library; новые продуктовые зависимости не нужны.

**Spec:** [2026-09-30-voice-chat-design.md](./2026-09-30-voice-chat-design.md), письменная спецификация согласована владельцем 2026-09-30 («продолжаем»).

## Global Constraints

- Рабочая ветка `feat/217-voice-chat`, worktree `.worktree/voice-chat-217`, задача #217. Основной checkout `feat/voice-chat` не изменять.
- Использовать итоговый UI #210 и зрителей #214. На момент плана #214 открыт, head `e6da26e3bf1fde265f0abd49e49fa769cbc2999b`; состояние зависимости проверить перед выполнением.
- Один канал комнаты; игроки и зрители могут говорить/слушать. Боты исключены. Reload начинает с `off`.
- `VoiceStatus = off | connecting | connected | interrupted`; громкости 0–200%, default 100, максимальное произведение gain 4.
- Permission timeout 30 000 ms; call setup timeout 15 000 ms; disconnect grace 2 000 ms; пять retries с задержками `[1000, 2000, 4000, 8000, 15000]` ms.
- Микрофон запрашивать только по действию пользователя; отказ/отсутствие/таймаут дают слушателя. Повторное включение через сервис; при живом захвате использовать существующий поток.
- Все запросы разрешений frontend — через сервис. Clipboard write выполняется непосредственно в click без обязательного предварительного async query.
- Голос и настройки не сериализуются в session/keeper persistence. Настройки в памяти комнаты связаны с `memberId`.
- PeerJS и RTCPeerConnection остаются в `network/transport`; никаких сетевых объектов во frontend pages или UI-kit.
- EN/RU copy через `@release/translation`; UI без i18next. CSS Modules, design tokens, Typography; новые source comments на английском.
- Page tests только в `__tests__/`; `app/router.ts` не редактировать. Общий рефакторинг `useLobby`, новая host migration и новые серверы вне объёма.

## Review Focus

1. Разрешение микрофона приходит после выхода/смены комнаты: остановить новый поток, не включить старую или новую voice-сессию — tests Tasks 1, 6, 7.
2. Браузер не поддерживает query конкретного разрешения, но поддерживает операцию: сохранить microphone/clipboard действие и user activation — tests Tasks 1, 2.
3. PeerJS сообщает ошибку недоступного аудио-peer через глобальный `peer.error`: голос прерывается, работающая игра продолжается; ошибка игрового dial всё ещё видна — tests Tasks 3, 7.
4. Звонок приходит до канонического roster, два слушателя входят одновременно: не передавать микрофон неизвестному входу, восстановить одну пару после roster — tests Tasks 4, 6.
5. Участник уходит/меняет peerId после local mute и громкости 200%: закрыть старый звук, сохранить настройки для memberId и не ждать ушедшего peer — tests Tasks 5, 6, 7.
