# Неоднозначности правил — открытые вопросы

Перевод [`2026-08-11-rules-ambiguities-open-questions.md`](./2026-08-11-rules-ambiguities-open-questions.md). Нумерация та же, чтобы вопросы и ответы сходились между версиями.

Каждый вопрос здесь — место, где [`docs/rules-board-game.md`](../rules-board-game.md) оставляет свободу, а движок выбрал за него: не решением, а тем, как получилось при реализации. **«Оставить как есть»** — совершенно нормальный ответ; смысл в том, чтобы это перестало быть случайностью.

Охватывает [#76](https://github.com/MythHand/ReleaseBoardGameP2P/issues/76) (вопросы 1–8) и [#74](https://github.com/MythHand/ReleaseBoardGameP2P/issues/74) (вопросы 9–11).

К каждому вопросу приложена рекомендация. **«Согласен с рекомендацией» — полноценный ответ.**

Вопрос **7** помечен как **технический** — он про устройство движка, а не про правила, и ответа не требует.

Ссылки на строки ниже всё равно указывают на него — другого письменного текста нет. Если цитата выглядит неверной, дело скорее всего в файле, а не в вопросе.

## DDoS

- [ ] **1. Можно ли отбить DDoS картой защиты?**

  Hotfix, Rubber Ducky и PR Approved перечисляют свои цели и DDoS в них нет ([правила :110](../rules-board-game.md)). А Rollback ([:114](../rules-board-game.md)), Not a Bug ([:118](../rules-board-game.md)) и Works on my Machine ([:122](../rules-board-game.md)) написаны как «Отменяет атаку» — без списка карт. Значит, они либо покрывают DDoS, либо нет, и текст не говорит, что именно.

  Сейчас DDoS срабатывает сразу и отбить его нельзя ([`release.ts:189`](../../packages/engine/src/fake/release.ts)).

  **Рекомендация: оставить неотбиваемым.** DDoS ничего не уничтожает — возвращает релиз в руку или убивает Monitoring, — то есть это самая мягкая атака в игре, а три «безадресные» защиты — самые редкие карты. Разрешить им отменять DDoS значит тратить лучшие ответы игры на её самую слабую угрозу.

- [ ] **2. Можно ли сыграть DDoS по только что выложенному релизу под Code Review?**

  «DDoS — единственная атака, работающая против защищённого релиза» ([:59](../rules-board-game.md)). Code Review можно приложить только в момент выкладывания релиза, поэтому фраза читается как про этот самый момент.

  Сейчас такая ситуация недостижима: защищённый релиз не открывает окно реакции, а DDoS играется только в свой ход. Защищённый релиз нельзя атаковать «в моменте» вообще — то есть строка :59 не описывает ни одной ситуации, до которой движок может дойти.

  **Рекомендация: открывать окно и для защищённого релиза, но пускать в него только DDoS.** Это единственное прочтение, при котором фраза что-то означает. Альтернатива — «можно сыграть DDoS позже, в свой ход» — и так покрыта обычной игрой, и тогда фраза лишняя.

## Security Bug

- [ ] **3. Какой именно свой релиз нужен, чтобы атакованный уходил в сброс, а не к вам?**

  «если у вас выложен Release в зоне релиза, атакованный Release отправляется в сброс» ([:100](../rules-board-game.md)) читается как *любой* релиз. Движок читает это как *тот же слот* ([`attacks.ts:43`](../../packages/engine/src/fake/attacks.ts)): кража происходит, если у вора соответствующий слот ещё свободен.

  **Рекомендация: как в движке — тот же слот.** При буквальном прочтении игрок с одним релизом уже никогда никого не обворует, и карта почти мертва у того, кто впереди. Послотовое прочтение сохраняет её живой и совпадает с тем, что зона устроена по типам.

- [ ] **4. Виден ли всем неудачный запрос Security Bug?**

  Правила молчат. Движок сообщает о промахе всем ([`handAttacks.ts`](../../packages/engine/src/fake/handAttacks.ts)).

  **Рекомендация: оставить публичным.** Приватный промах превращает карту в бесплатную разведку, которую можно повторять до попадания, и стол теряет понимание, кого на чём поймали.

## Monitoring и выбывание

- [ ] **5. Monitoring защищает автоматически или это один из вариантов на выбор?**

  «угроза от них игнорируется» ([:86](../rules-board-game.md)) читается как автоматически. Движок предлагает Monitoring как один из способов нейтрализации наравне с Debugger и жертвой релиза ([`triggers.ts:19`](../../packages/engine/src/fake/triggers.ts)) — то есть игрока, у которого есть и Monitoring, и Debugger, можно подтолкнуть потратить Debugger.

  **Рекомендация: автоматически.** «Игнорируется» описывает то, что происходит с угрозой, а не выбор, предлагаемый игроку; и никто в здравом уме не выберет платный вариант, когда рядом лежит бесплатный.

- [ ] **6. Куда уходят карты выбывшего игрока?**

  Правила не говорят ([:177](../rules-board-game.md)). Движок отправляет руку и зону в сброс.

  **Рекомендация: оставить сброс.** Им нужно куда-то деться, а сброс — единственная открытая стопка, и это оставляет их доступными для карт, которые в сброс лезут.

- [ ] **7. Кто ходит первым?** *(технический — ответа не требует)*

  Правила задают «социальное» правило ([:20](../rules-board-game.md)); движок сажает первым хоста. Записано только чтобы расхождение было где-то зафиксировано.

- [ ] **8. Тратит ли релиз, выложенный по событию AI Release, лимит «один релиз за ход»?**

  Не оговорено. Движок считает, что нет: `releasesPlayed` растёт только когда игрок выкладывает релиз сам ([`release.ts:52`](../../packages/engine/src/fake/release.ts)).

  **Рекомендация: не тратит.** Лимит ограничивает то, что игрок делает по своей воле; событие AI происходит с ним, и брать за это плату значило бы, что удачный добор стоит хода.

## Works on my Machine

Отражение разворачивает атаку на того, кто её бросил. «Эффект карты атаки оборачивается против самого атакующего» ([:122](../rules-board-game.md)) — из слова «эффект» следуют три вещи, которые движок сейчас решает сам.

- [ ] **9. Пробивает ли отражённая атака Code Review?**

  Code Review делает релиз неуязвимым для Bug, Out of Memory, Legacy Code и Security Bug, «даже с sudo-усилением» ([:132](../rules-board-game.md)). Отражение в движке берёт первый занятый слот атакующего, не проверяя защиту, а приложенный Code Review уходит в сброс вместе с релизом.

  **Рекомендация: не пробивает — отражённая атака остаётся той же атакой, защита работает.** Иначе Works on my Machine становится способом протащить любую атаку мимо Code Review, а это сильнее, чем заявляет любая из двух карт.

- [ ] **10. Отражённый Security Bug — отражающий забирает релиз себе или релиз уничтожается?**

  Собственный эффект Security Bug — «забираете карту релиза в свою зону релиза» ([:100](../rules-board-game.md)). При отражении движок уничтожает релиз атакующего, а не перемещает его.

  **Рекомендация: отражающий забирает.** Карта отражает *эффект*, а эффект — это «забрать». Уничтожение — эффект другой карты, и он возникает лишь потому, что путь отражения не передаёт, кто крадёт.

- [ ] **11. По какому релизу атакующего бьёт отражённая атака?**

  Правила не говорят. Движок берёт первый занятый слот в фиксированном порядке — то есть всегда Frontend, если он есть. Это порядок массива, а не решение.

  **Рекомендация: выбирает отражающий.** Это его карта и его момент, а атакующий свою цель уже выбрал; фиксированный порядок молча делает Frontend самым опасным релизом из всех.

  Если выбор нежелателен, подойдёт любое явное правило — «выбирает атакующий», «тот же слот, что и у исходной цели», — но его нужно проговорить, потому что сейчас это случайность.
