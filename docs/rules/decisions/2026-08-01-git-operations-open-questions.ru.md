## Добор и колоды

- [x] **1. Что означает обязательный добор в режиме Base, когда колода разделена?**

  [Правила, «Добор карты»](../rules-board-game.md#добор-карты) — «Игрок обязан взять одну карту сверху основной колоды… При разделенной колоде добора карта берется из всех колод.» [Правила, «Последствия Git Branch»](../rules-board-game.md#последствия-git-branch) задают Base как «Добор из всех колод», а Strategic как «Добор только из одной колоды».

  1. По одной карте с верха **каждой** колоды: при двух колодах игрок за ход берёт две карты. Strategic — одна карта, игрок сам выбирает колоду.
  2. Колоды считаются одним источником: в Base игрок свободно выбирает, откуда взять одну карту, в Strategic он привязан к одной колоде. Количество взятых карт не меняется никогда.

  **Рекомендация: 1.** Таблица режимов имеет смысл только если Base берёт из всех колод — иначе Strategic просто повторяет Base другими словами, а Git Branch ничего не даёт в том самом режиме, который правила называют основным.

  **Это главный вопрос списка.** От него зависит, чем вообще является Git Branch.

  **Ответ.** «В вопросе логическая проблема от неверной интерпретации и путаницы понятий. И не
  актуальная информация о правилах (они были доработаны). Базовый добор подразумевает всегда по одной
  верхней карте из всех колод добора. Стратегический вариант подразумевает выбор, из какой именно
  колоды добора берётся карта. Разные колоды добора — это разные источники добора. Рекомендация также
  искажает понимание карты Git Branch — пример фундаментальной ошибки понимания правил».
  **В игре.** Так: в Base — по карте с каждой колоды, в Strategic — одна карта с колоды, которую
  выбрал игрок.
  **В спеке.** [`modes.md`, «Последствия Git Branch»](../modes.md#последствия-git-branch--modegit);
  [`general.md` §4](../general.md#4-ход-игрока).

- [x] **2. (Технический вопрос — ответ не нужен.)** Если Base берёт из всех колод, реализовать это одним неделимым действием «добор» или обязанностью «взять из каждой колоды по отдельности»?

  Триггер-карта срабатывает сразу в момент добора и может открыть ожидание решения (Error 503 требует нейтрализации). В движке ожидание может быть только одно за раз. Неделимый добор из двух колод, где первая карта — триггер, потребовал бы очереди ожиданий. Обязанность «по колоде за раз» этого избегает.

  **Ответ (вместе с 6).** «При взятии карт из нескольких колод одновременно карты берутся
  последовательно, карта 503 ставит процесс на паузу, пока не будет отбита». «Действие добора
  происходит по кнопке-триггеру и запускает последовательный добор из каждой существующей колоды
  добора, в процессе добора разыгрывание карт с руки невозможно (как в обычной фазе игры)».
  **В игре.** Так: одно нажатие — добор по всем колодам по очереди, Error 503 останавливает серию до
  ответа, розыгрыш во время добора отклоняется.
  **В спеке.** [`general.md` §4](../general.md#4-ход-игрока);
  [`resolution.md` §8](../resolution.md#8-добор-и-триггеры).
  **Онлайн.** За столом игрок берёт с каждой колоды руками, в игре одна кнопка запускает всю серию.
  Запрет играть между двумя колодами — следствие того, что добор стал одним действием.

- [x] **3. Разделяет ли Git Branch уже разделённую колоду?**

  [Правила, «Git Branch»](../rules-board-game.md#git-branch) — «Разделите одну колоду добора (зелёную) на две.» Если карта сыграна дважды: две колоды превращаются в три? Есть ли предел?

  **Рекомендация:** без предела, N → N+1.

  **Ответ.** «Git Branch не привязан к понятию одной определённой колоды. Описание говорит, что нужно
  выбрать колоду добора, которую нужно разделить. На столе одна колода — карта Git Branch делит её на
  2 без вопросов. На столе 2 колоды — игрок выбирает, какую из колод необходимо разделить, и именно
  эта колода делится на 2 — итого на столе 3 колоды, и т. д. Предела нет (игра сама по себе имеет
  предел из механик игры, внешнего ограничения нет)».
  **В игре.** Так: при одной колоде карта играется сразу, при нескольких колоды подсвечиваются, и
  розыгрыш ждёт клика по одной из них.
  **В спеке.** [`cards.md`, Git Branch](../cards.md#git-branch--operation-git-branch--тираж-3--sudo).

- [x] **4. Где именно проходит разделение?**

  За столом игрок снимает колоду где хочет. В цифровой версии этого выбора нет — если он не нужен по правилам.

  1. Ровно пополам.
  2. В случайном месте.
  3. Игрок выбирает сам — тогда нужен отдельный экран выбора.

  **Рекомендация: 1.** Смысл карты в самом факте разделения, а не в том, где прошёл разрез.

  **Ответ.** «Колода делится ровно пополам, для нечётных — ок, если в одной из разделённых колод будет
  на 1 карту больше. Если в колоде добора всего одна карта, то фактически ничего не произойдёт, карта
  Git Branch просто уходит в сброс».
  **В игре.** Так.
  **В спеке.** [`cards.md`, Git Branch](../cards.md#git-branch--operation-git-branch--тираж-3--sudo).
  **Онлайн.** За столом колоду снимают там, где легла рука, в игре — всегда ровно пополам.

- [x] **5. Что именно делает sudo Git Branch?**

  [Правила, «Git Branch»](../rules-board-game.md#git-branch) — «sudo Git Branch: **и** переверните сброс — он будет использоваться как новая колода добора, не перемешивайте карты.» Союз «и» читается как «вдобавок к разделению»: тогда колод становится на две больше — одна из разреза, одна из перевёрнутого сброса (порядок сохраняется, карты не тасуются).

  Это верно, или sudo-вариант заменяет разделение, а не дополняет его?

  **Ответ.** «sudo Git Branch не искажает карту: остаётся логика разделения колоды добора, а сброс
  добавляется как независимая от основного действия ещё одна колода добора. То есть если на столе была
  1 колода карт, применили sudo Git Branch — колода добора разделилась на 2, и плюс 3-й колодой добора
  стал перевёрнутый сброс: итого из 1 колоды добора и сброса вышло 3 колоды добора и пустой сброс».
  **В игре.** Так.
  **В спеке.** [`cards.md`, Git Branch, sudo](../cards.md#git-branch--operation-git-branch--тираж-3--sudo).

- [x] **6. Сбрасывает ли Git Merge уже частично выполненный добор?**

  Актуально только если в вопросе 1 выбран вариант 1. Игрок взял карту из первой колоды, затем сыграл Git Merge — колоды объединились в одну, из которой он уже брал. Должен ли он брать ещё раз?

  **Рекомендация:** нет, обязанность считается выполненной.

  **Ответ.** «Нет: действие добора происходит по кнопке-триггеру и запускает последовательный добор из
  каждой существующей колоды добора, в процессе добора разыгрывание карт с руки невозможно (как в
  обычной фазе игры)». Значит, Git Merge посреди добора не бывает.
  **В игре.** Так: розыгрыш во время добора отклоняется.
  **В спеке.** [`general.md` §4](../general.md#4-ход-игрока).

- [x] **7. Что происходит с пустой колодой добора?**

  Если одна из колод опустела, а по правилам режима Base нужно брать из всех — пустая просто пропускается?

  И отдельно: что происходит, когда пусты **все** колоды добора? Замешивается ли сброс обратно, или единственный способ вернуть карты в игру — Git Merge?

  **Ответ.** «Тут 2 кейса. В первом случае карт для добора не осталось совсем — тогда берётся сброс,
  перемешивается, и появляется новая 1 колода добора. Второй случай — когда колод добора было
  несколько, например 3, и закончилась 2-я из 3: значит, её больше нет, на столе остаётся только 2
  колоды добора».
  **В игре.** Так.
  **В спеке.** [`general.md` §4](../general.md#4-ход-игрока), «Колоды добора не кончаются насовсем»;
  [`resolution.md` §8](../resolution.md#колода-кончилась-во-время-добора);
  [`cards.md`, Git Merge](../cards.md#git-merge--operation-git-merge--тираж-2--sudo). В тексте правил о
  том, что колоды кончаются, нет ничего — правило целиком из этого ответа.

## Сброс и информация

- [x] **8. Сброс открыт всем игрокам?**

  Cherry-pick ([Правила, «Git Cherry-pick»](../rules-board-game.md#git-cherry-pick), «выберите одну карту из всего сброса») и Inside ([Правила, «Карты AI-эффектов»](../rules-board-game.md#карты-ai-эффектов), «возьмите одну карту Release из сброса в руку») требуют, чтобы игрок видел весь сброс целиком.

  1. Сброс всегда открыт всем — так же, как он лежит на столе рубашкой вниз.
  2. Сброс раскрывается только тому игроку, который сейчас выбирает из него карту.

  **Рекомендация: 1.** Соответствует столу; вариант 2 прячет информацию, которую правила не прячут.

  **Ответ.** «Сброс открытый — для карт доставания карт из сброса отдельные UI-механики просмотра
  сброса по необходимости. То есть в процессе игры просто так смотреть сброс нельзя (хотя карты в UI
  лежат лицом вверх), но по эффектам карт есть отображение сброса. В
  [PR #78](https://github.com/MythHand/ReleaseBoardGameP2P/pull/78) есть визуализация карт, которые
  работают со сбросом, в плейграунде».
  **В игре.** Так: куча сброса не открывается ни кликом, ни наведением; весь сброс показывают только
  Cherry-pick и Inside.
  **В спеке.** [`cards.md`, Git Cherry-pick](../cards.md#git-cherry-pick--operation-git-cherry-pick--тираж-3--sudo).
  **Онлайн.** За столом стопку сброса можно взять и просмотреть, в игре — нет.

- [x] **9. Должна ли игра помнить, что игрок знает про колоду?**

  Sudo Cherry-pick кладёт вторую карту наверх колоды добора «не показывая другим игрокам» ([Правила, «Git Cherry-pick»](../rules-board-game.md#git-cherry-pick)) — то есть этот игрок знает следующую карту, а остальные нет.

  1. Игра это учитывает и показывает игроку, что он знает верхнюю карту.
  2. Не учитывает: карта легла наверх, игрок сам её помнит — как за столом.

  **Рекомендация: 2 для этой части.** Но отвечать стоит с оглядкой на Git Rebase (следующая часть) — он требует того же самого, только в большем объёме: «посмотрите три верхние карты… и измените их порядок» ([Правила, «Git Rebase»](../rules-board-game.md#git-rebase)).

  **Ответ.** «Согласен с рекомендацией, так и задумано».
  **В игре.** Так: в состоянии игры нигде не записано, кто знает верх колоды.
  **В спеке.** [`cards.md`, Git Rebase, «Знание о колоде»](../cards.md#git-rebase--operation-git-rebase--тираж-3--sudo).

- [x] **10. На какую колоду ложится вторая карта sudo Cherry-pick?**

  Актуально, только когда Git Branch уже разделил колоду. На первую по счёту, или игрок выбирает сам?

  **Ответ.** «Если колод добора несколько, то класть в первую из множества».
  **В игре.** Так.
  **В спеке.** [`cards.md`, Git Cherry-pick, sudo](../cards.md#git-cherry-pick--operation-git-cherry-pick--тираж-3--sudo).

- [x] **11. Что происходит, если в сбросе нечего взять?**

  Сброс пуст, или — для Inside, который берёт только карты Release — в сбросе нет ни одной карты Release. Карта тратится впустую и ничего не происходит, или сыграть её в такой ситуации нельзя?

  **Ответ.** «Тогда шаг взятия из сброса пропускается из-за невозможности. Сыграть можно — это игровой
  момент с последствиями для игрока, когда тот затупил».
  **В игре.** Так. Cherry-pick, когда в сбросе нечего взять: карта тратится, выбор не открывается.
  Inside без релизов в сбросе — ничего не происходит. Inside с ровно одной картой релиза — она
  берётся без вопроса. Иначе Inside выкладывает только карты релизов из сброса, и игрок берёт одну —
  тип несёт сама карта.
  **В спеке.** [`cards.md`, Git Cherry-pick, «Невозможный выбор»](../cards.md#git-cherry-pick--operation-git-cherry-pick--тираж-3--sudo);
  [`cards.md`, Inside](../cards.md#inside--ai-inside--тираж-2).

## Что эти ответы поменяли в движке

Записано 02.08.2026, до того, как части были собраны. Сегодня в движке есть все пять.

1. **Добор перестаёт быть действием на одну карту.** `DRAW` становится последовательностью по всем колодам, которая переживает ожидание решения. `turn.hasDrawn` не может остаться булевым, и у движка появляется состояние «идёт добор». Это изменение основного цикла игры, а не только Git-операций, и оно едет в одной части с Git Branch, потому что именно Git Branch делает несколько колод достижимыми.
2. **Розыгрыш с руки во время добора запрещён** — правило, которого раньше не было.
3. **Git Branch нужна цель — колода**, поэтому у цели розыгрыша появляется вариант «колода».
4. **Колода из одной карты — настоящая ветка:** Git Branch на ней — законный розыгрыш, который сбрасывает карту и ничего не меняет.
5. **Здесь ничего не требует знания о колоде или параллельного ожидания**, поэтому части 1 и 2 не задевают изменений формы, которые принесёт System Upgrade.
